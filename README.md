## 👀 长什么样

会话头部右侧多一枚小电源图标 ⚡，**不抢位置**、**不遮**最小化 ➖ / 隐藏 👻 / 关闭 ❌ 那组窗口按钮（这点我盯得很死，谁也别想挤到它们）

点开是个小菜单，里面**只有两个按钮**，干干净净：

| 按钮 | 干了什么 |
| --- | --- |
| **⚡ 重启** | 结束当前进程 → 等端口让出来 → 按**原来的命令行**重新拉起一份 🔁 |
| **⏻ 关闭** | 结束当前进程，不自动拉起 🌙 |

两个按钮都要**点两次** 👆👆：
第一次是「你真的想好了吗 🤨」，第二次才是「好，动手 🔨」

## ⚠️ 重启时弹「应用无法启动或已意外停止」——点里面的「重启」就行

点重启后，屏幕上会跳出这么一个吓人的窗口 😱：

![重启时弹出的窗口](docs/restart-dialog.png)

**🫂 别慌。这个窗口不是来骂你的，它是来帮你重启的。**

原因贼直白 🧾：这插件的重启就是**真的把进程杀了** 🔪
DSH Desktop 的外壳发现自己怀里的宿主进程突然没了 💀，就尽职尽责地报了一次 ——
它不知道这是你亲手按的电源键，它只知道自己被杀了 🥲

**而这个窗口，恰好就是我们借来重启的通道** 🤝
它上面那排按钮里的**「重启」**，执行的是 Electron 官方的 `app.relaunch()` ——
官方、可靠、能正确重建整个应用 ✅

完整流程长这样 👇

1. 点「⚡ 重启」👆👆
2. 菜单提示「正在重启：在弹出的窗口里点『重启』↻」
3. 弹这个窗 → 正常，**点中间的「重启」** ✅
4. ⏳ 几秒后 DSH 自己重启完，页面回来

> 🔑 **一句话记住**：弹窗出现 = 进程真的死了 = 该点「重启」了。
> ⛔ **别点 ✕** —— 那等于按「退出」（`cancelId` 就是退出），进程会直接消失，不会重新起来。

窗口里那句 `MODULE_NOT_FOUND` 是崩溃报告要写堆栈的副产品 🧩
**不是你插件坏了** 🙏 是「进程被突然打断」这件事本身写出来的。

### 🤔 为什么这个弹窗消不掉（诚实交代）

我把 Desktop 主进程的代码翻了一遍，结论很明确：**它消不掉，插件层做不到。**

- 弹窗由主进程的 `DesktopFatalRecovery.report()` 弹出，触发条件是「host 子进程非预期退出」。它靠内部一个 `shuttingDown` 标志区分「正常退出」和「意外死亡」，而这个标志只有应用自己的退出流程能设。
- 主进程确实有官方重启姿势：`app.relaunch() + quitWithoutConfirmation()`。但它在 **Electron 主进程**里，插件跑在 **host 子进程**里，够不着 🙅
- IPC 通道表里只有快捷键、目录选择、更新、主题这些，**没有任何一个能触发重启**。

所以：**只要是真的杀进程，主进程就必然报告一次。** 这是外壳的固定行为，不是 bug。

**既然消不掉，那就顺着它来** —— 用它的「重启」按钮完成重启，这就是现在的做法。

### 🐛 踩过的两个坑

**坑一：「点 ✕ 之后好像没重启」** 🫠

对，✕ 就是「退出」，永远不会重启。这是弹窗的 `cancelId` 决定的，不是插件的锅。

**坑二：自己 spawn 新进程，和弹窗抢方向盘** 🤡

试过用 `ELECTRON_RUN_AS_NODE` 只重放 host 子进程 —— 进程能起来，
但弹窗还在，用户点 ✕ 反而把刚起来的一切关掉。

**最终方案**：不自建 spawn 了，把重启交给弹窗的「重启」按钮，走官方 `app.relaunch()` 🎯

> 💡 用「⏻ 关闭」则完全不会弹窗 —— 关闭是你主动要它走，DSH 会安静退出 😴
> 只有「重启」这种「先死一次再复活」的操作 🧟，外壳才会误以为出事了。

## 🛠️ 它是怎么工作的（技术党进）

### ⚡ 重启

**不自建 spawn。** 点重启后，插件让 host 进程以**非零退出码**结束 ——
主进程据此判定「宿主意外停止」，弹出恢复对话框；
你在框里点「重启」，执行的是 Electron 官方的：

```js
app.relaunch()
quitWithoutConfirmation()
```

这是 DSH 自己设计好的重启路径，不依赖猜启动命令、不会撞端口、能正确重建整个应用 ✅

**为什么不自己拉起？** 试过，打不过 🤷
主进程一旦发现 host 消失就会弹框，自建的进程和弹框抢方向盘：
新进程可能起来了，但框还在，用户点 ✕（= `cancelId` = 退出）反而把一切关掉。
顺着官方的路走，反而最稳。

### ⏻ 关闭

给 launcher 的 `appExit` 钩子打个招呼（没有钩子就直接 `process.exit(0)`），
外壳视为正常退出，**不弹窗** 😴

### 🔒 安全边界

- 只接受**同源** `POST`，跨站一律 403
- 端口只在本机 loopback 监听
- 除重启 / 关闭外没有任何其他动作

## ❓ 常见问题

**Q：点重启后弹了「应用无法启动或已意外停止」，是不是插件写坏了？** 😰

不是 🙅 这是主进程在报告「我的宿主子进程没了」。
**在弹窗里点「重启」**（中间那个按钮），走官方 `app.relaunch()` 重新起来 ✅
⛔ **别点 ✕** —— 那等于按「退出」，进程会直接消失。

**Q：弹窗能彻底关掉吗？每次重启都弹好烦** 😤

不能，插件层做不到 🙅 详见上面「为什么这个弹窗消不掉」——它在 Electron 主进程里，而插件跑在 host 子进程里，够不着 `app.relaunch()`。
**但可以避开它**：用「⏻ 关闭」就不弹，因为你主动要它退出，外壳视为正常退出 😴

**Q：我点了 ✕，但好像没重启？** 🤔

对，✕ 等于「退出」，就是不会重启 😅 这是弹窗的 `cancelId` 决定的，不是插件的锅。
**下次点中间那个「重启」按钮就行** ✅

**Q：重启后端口变了，我原来的浏览器地址打不开了？** 🤔

正常 🙂 DSH 会自己挑端口。重新从桌面应用或启动器进入即可。

**Q：为什么关闭不弹窗，重启却弹？** 🤨

关闭是你主动要它退出 😴 外壳视为正常退出；
重启是「先死一次再复活」🧟 外壳在中间那一刻看到的是「意外消失」，所以报了一次 📢
—— 而这个弹窗恰好就是我们借来重启的通道 🤝

**Q：能批量重启多个 DSH 吗？** 🤖

不能，它只管当前这一个进程。想开多个请用多 profile，别指望它变集群管理器 😅

**Q：关闭之后数据会丢吗？** 💾

不会 🙅 会话、配置、插件全都在磁盘上躺着。关闭只是让进程退出，不是删库跑路 🔥

## 🔬 自检

```bash
curl http://127.0.0.1:<port>/dsh-power-switch/api
```

返回里能看到当前 `pid` 🆔、`port` 🔌、`platform` 🖥️、`restartable` ✅

它不会撒谎 —— 如果 `restartable: false`，说明它没能推断出启动命令，这时候它会**拒绝**重启而不是瞎猜 🙅‍♂️（宁可不动，也不乱动，这点很讲究）
