## 👀 长什么样

会话头部右侧多一枚小电源图标 ⚡，**不抢位置**、**不遮**最小化 ➖ / 隐藏 👻 / 关闭 ❌ 那组窗口按钮（这点我盯得很死，谁也别想挤到它们）

点开是个小菜单，里面**只有两个按钮**，干干净净：

| 按钮 | 干了什么 |
| --- | --- |
| **⚡ 重启** | 结束整个 DSH（含桌面主进程），随后自动拉起一个全新的 🔁 |
| **⏻ 关闭** | 结束整个 DSH，不自动拉起，安静地走 🌙 |

两个按钮都要**点两次** 👆👆：
第一次是「你真的想好了吗 🤨」，第二次才是「好，动手 🔨」

## 🎉 关于那个崩溃弹窗：这版把它干掉了

老版本会弹这个：

```
Error: dsh desktop host stopped: ...
```

**新版本不会了** ✅ 因为这次杀的是**桌面主进程**，不是宿主子进程。

道理很直白 🧾：

- 那个弹窗是**桌面外壳（主进程）**弹的 —— 它盯着自己的宿主子进程，发现没了就报一次 📢
- 那就别让它有机会报啊 —— **把主进程一起送走** 🔪
- 主进程都没了，谁来弹框？🤷‍♀️

剩下的收尾由宿主自己完成：
主进程一死，宿主那边的 IPC 通道就断了，宿主监听着 `disconnect`，
于是它**自己走一遍正常关闭流程**（会话日志好好落盘 📝），然后安静退出 😴

> 🔑 **一句话记住**：以前杀的是「儿子」，爸爸在旁边看着当然要哭；
> 现在直接把「爸爸」请走，全家一起安静退场 🤐

### 🐛 试错记录（免得你也踩一遍）

| 方案 | 结果 |
|---|---|
| 只杀宿主子进程（老版本） | ⚠️ 功能没问题，但主进程必然报一次「宿主停止」 |
| 退出码设 0 想骗过它 | ❌ `fail()` 的两个分支都触发，文案从「exited」变「stopped」而已 |
| 想设 `stopping` 标志 | ❌ 那是主进程私有状态，插件够不到 |
| 找 IPC 白名单走正门 | ❌ 只认 `ready` / `shutdown-complete` / `platform-session` / `fatal`，没有重启入口 |
| **杀主进程（不带 `/T`）** | ✅ **本次方案**：没人能弹窗，宿主自己优雅退出 |
| 杀主进程**带** `/T` | ❌ 会连宿主一起强杀，宿主来不及落盘，等于拔电源 🔌 |

那个 `/T`（连同子进程）看着更彻底，其实是坑 —— **不带它才是对的** 🙅

## 🛠️ 它是怎么工作的（技术党进）

### ⚡ 重启

四段接力，没有任何魔法：

1. **自省** 🪞：从 `process.pid` / `process.ppid` / `process.execPath` 现场问出
   「我是谁、我爸是谁、我是被哪个 exe 启动的」，**不猜** profile 🙅 **不写死** 路径 🙅
2. **接力** 🏃：拉起一个 `detached` 的 helper。它不在任何进程树里，所以父进程死光它也活着
3. **送走** 🔪：helper 等一小会儿（先把 HTTP 响应吐完），然后 `taskkill /PID <主进程> /F`
   —— 注意**没有 `/T`**，只杀主进程本身
4. **重生** 🧟：主进程没了 → 宿主因 IPC 断开自行优雅退出 → helper 等旧实例彻底走干净、端口空出来
   → 用原 exe 拉起新实例 → 确认进程活下来 → helper 自己退出

> 为什么必须等干净？因为 Electron 有**单实例锁**（`requestSingleInstanceLock`）🔒
> 旧主进程没退利索就 spawn 新的，新实例会发现自己不是「老大」，直接 `quit()` 自杀。
> 所以 helper 会重试最多 5 次，每次间隔 3 秒 —— 手慢不要紧，起来就行 😌

**环境变量要清干净** 🧹：拉起前会把 `ELECTRON_RUN_AS_NODE` 和 `DSH_DESKTOP_NODE_EXECUTABLE` 删掉。
不删的话新实例会以 node 模式启动 —— 进程是起来了，但**没有窗口**，等于白起 🙃

### ⏻ 关闭

同一条路，只是最后不 spawn。主进程走人 → 宿主优雅退出 → 结束 🌙

### 🖥️ 前端为什么不用刷新

旧页面跟着旧进程一起消失了，刷新它没有意义 🙅
点完按钮就显示「正在关闭 / 正在重启」，然后等页面自己断线。
新实例起来是个**新的地址、新的页面**，从桌面应用或启动器进去就行。

如果十几秒后页面还活着 —— 说明那一下没生效，它会老实告诉你「没反应，再点一次？」🤔

### 🔒 安全边界

- 只接受**同源** `POST`，跨站一律 403
- 端口只在本机 loopback 监听
- 除重启 / 关闭外没有任何其他动作

## ❓ 常见问题

**Q：重启后还弹「宿主停止」吗？** 😰

**不弹了** 🎉 这版把弹框的源头（主进程）一起请走了，详见上面那节。
如果你还看到弹框，八成是装的是老版本 —— 升级一下就好。

**Q：那我现在怎么知道重启成功了？** 🤔

页面会自己断掉，然后你从桌面应用重新进 —— 看到界面就是成功了 ✅
没成功的话 helper 会弹一个原生提示框告诉你「应用没起来，请手动启动」，不会闷声装死 🤐

**Q：为什么要杀主进程，不能温和一点吗？** 🥺

试过了，温和不了 🙇 主进程对「宿主消失」这件事的反应是写死的：
不管退出码是 0 还是非 0，都会报一次。插件跑在子进程里，碰不到它的私有状态。
所以换个思路 —— 既然它一定要报，那就让它**没机会报** 😤

**Q：那我为什么还要用这个插件？** 🤔

因为它就在会话头部，两下点击，不用翻菜单；
而且它**同时提供「关闭」** —— 现有同类插件几乎都只做重启。

**Q：重启后端口变了，我原来的浏览器地址打不开了？** 🤔

正常 🙂 DSH 会自己挑端口。重新从桌面应用或启动器进入即可。

**Q：能批量重启多个 DSH 吗？** 🤖

不能，它只管当前这一个进程。想开多个请用多 profile，别指望它变集群管理器 😅

**Q：关闭之后数据会丢吗？** 💾

不会 🙅 会话、配置、插件全都在磁盘上躺着。关闭只是让进程退出，不是删库跑路 🔥
而且宿主走的是自己的优雅关闭流程，日志会好好落盘 📝

## 🔬 自检

```bash
curl http://127.0.0.1:<port>/dsh-power-switch/api
```

返回里能看到当前 `pid` 🆔、`port` 🔌、`platform` 🖥️、`restartable` ✅

它不会撒谎 —— 如果 `restartable: false`，说明它没找到 Electron 主进程（比如跑在纯 Web 形态下），
这时候它会**拒绝**重启而不是瞎猜 🙅‍♂️（宁可不动，也不乱动，这点很讲究）
